<objective>
Replace the invisible 1px there-and-back nudge with realistic random cursor
roaming. On each -interval tick the service asks a pure domain planner for a
glide path from the current cursor position to a fresh uniformly-random target
inside the main-display bounds, then drives the pointer through that path with
short inter-step pauses, stopping promptly on ctx cancellation (including
mid-glide).

Purpose: deliver the visible, human-like activity behavior the user wants while
preserving the hexagonal layering (pure cgo-free domain + service, cgo isolated
to the darwin adapter) and the zero-runtime-dependency constraint.

Output: a new domain movement planner with deterministic tests; a reshaped
Pointer port (MoveTo/Position/Bounds) with a regenerated mock; a rewritten
KeeperService that roams once per tick; a CoreGraphics adapter implementing
absolute move / current position / main-display bounds; updated main.go wiring;
all gates green.
</objective>

  <name>Task 1: Pure domain movement planner + deterministic tests</name>
  <files>internal/activity/domain/planner.go, internal/activity/domain/planner_test.go</files>
  <behavior>
    - Planner exposes a method that, given current position (x, y), screen
      bounds (width, height), and an injected random source, returns an ordered
      slice of intermediate points ending exactly at a random target.
    - Random source is injected behind a small seam (an interface with the
      float/int-picking methods the planner needs, satisfied by *math/rand/v2
      Rand) so tests feed a deterministic stub and assert exact paths.
    - Target is uniform within bounds and clamped to [0,width) x [0,height);
      never negative, never >= width/height.
    - Path is continuous: consecutive points differ by a bounded step (no
      teleport); path length is on the order of ~20-60 steps.
    - Path's last element equals the target.
    - Edge cases covered by tests: cursor already at a corner; a 1x1 screen
      (bounds width=1,height=1 -> only valid point is (0,0)); target equal to
      current position (path is well-formed, ends at current point).
    - Invalid bounds (width<=0 or height<=0) return an error, no panic.
  </behavior>
  <action>
    Create Package-doc-free additions to `internal/activity/domain` (the package
    doc already lives in activity.go). Define a random-source seam interface
    named for its role (e.g. a source that yields an int in [0,n) and/or a
    float in [0,1)); *math/rand/v2 Rand satisfies it via its existing methods —
    keep the interface to only the methods actually used so it stays minimal and
    lint-clean. Define a `Planner` type with a constructor and a single method
    that plans a glide path: pick a uniform random target inside bounds, clamp
    to [0,width) x [0,height), then interpolate from current position to target
    over a bounded number of small steps, returning the ordered intermediate
    points with the target as the final element. Choose a fixed step count in
    the ~20-60 range (implementation detail); derive per-step deltas so no step
    exceeds a bounded magnitude. Keep the file cgo-free and os-free (no time, no
    C) so it builds under GOOS=linux. Respect the lint config: keep functions
    under the funlen/cyclop limits (split helpers if needed), name any numeric
    constants rather than leaving bare magic numbers in logic (mnd), and add
    godot-compliant doc comments on exported identifiers.
    Write `planner_test.go` (testify + a hand-injected deterministic source that
    is NOT a mockgen mock — this is domain, no port involved) asserting the
    behaviors above including all three edge cases.
