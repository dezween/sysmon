<objective>
Fix `make stop` silently failing to stop orphaned sysmon processes.

`stop` and `status` currently derive liveness solely from `$(PIDFILE)`. The pidfile desyncs
from reality in two ways: running `make start` twice overwrites the pidfile and orphans the
first instance forever, and `make clean` deletes the pidfile without killing anything. A real
orphan (PID 70263, alive since Aug 19, 2:44 of CPU) survived `make stop`, which reported
"sysmon is not running" and then unconditionally ran `rm -f $(PIDFILE)` anyway.

Purpose: make process liveness the source of truth, and demote the pidfile to a label that is
trusted only when it is corroborated by a live-process scan.
Output: a hardened `Makefile` — the only file this plan touches.

**Supersedes a recorded decision.** `.planning/STATE.md` > Accumulated Context > Decisions
currently states: "pidfile-based start/stop in Makefile retained as-is (not touched by this
refactor)." This plan explicitly supersedes that decision — the pidfile is retained, but it is
no longer the sole liveness signal. The plan SUMMARY must record the supersession so the quick
workflow can update that line in STATE.md.
</objective>

<constraints>
Scope is exactly one file: `Makefile`. Do not touch Go sources, README, CHANGELOG, CI, or add
any new file. No new dependencies — POSIX sh plus standard macOS (BSD) tooling only.

Match-precision facts, verified on the target machine during planning (do not re-derive):
- `/usr/libexec/sysmond` is a live macOS system daemon, and `pgrep -f sysmon` **does** return it.
  Any full-argument-list match is therefore unsafe for this binary name.
- `pgrep -x -U "$(id -u)" sysmon` returns nothing while only `sysmond` is alive — `-x` requires
  an exact match against the process *name* (`p_comm`), so `sysmond` is excluded by the trailing
  `d`, and `-U` restricts the scan to the invoking user's own processes.
- Matching on the process name rather than the argument list also removes any possibility of the
  recipe's own `/bin/sh -c ...` invocation matching itself, since that shell's name is `sh`.
- macOS `pgrep` accepts `-Lfilnoqvx`, `-d`, `-F`, `-G`, `-P`, `-U`, `-g`, `-t`, `-u`.
- BSD `sleep` accepts fractional seconds, so `sleep 0.2` is valid.

Makefile mechanics: every recipe line starts with a literal TAB; shell variables are written
`$$name`; a multi-line `if`/`for` must be one logical line (trailing ` \`) so its shell variables
stay in scope; keep the existing `@` prefixes and the existing `## target: description` comment
style above each target.
</constraints>

<tasks>

<task type="auto">
  <name>Task 1: Add the live-scan helper, rebuild stop around it, and chain clean to stop</name>
  <files>Makefile</files>
  <action>
Add a recursively-expanded make variable named `PGREP`, defined near the existing `PIDFILE` and
`INTERVAL` variables, whose value is `pgrep -x -U $$(id -u) $(BINARY)`. Use `=` (recursive), not
`:=` — with `=` the `$$` survives until recipe expansion and reaches the shell as a single `$`,
which is what makes the `id -u` command substitution run at recipe time. Above it, add a short
`#` comment explaining that `-x` matches the process name exactly so the unrelated macOS daemon
whose name is the binary name plus a trailing `d` is never matched, and that `-U` limits the scan
to the invoking user. Do not use `-f` anywhere, and do not use `pkill` — `stop` must report the
PIDs it acted on, which requires capturing the scan output.

Rewrite the `stop` recipe as a single logical shell line (backslash continuations) that:

1. Captures the live PID list: assign `live` from the `$(PGREP)` output, redirecting stderr to
   /dev/null and appending `|| true` so a no-match exit status of 1 never fails the recipe.
2. Captures the pidfile contents into `tracked` via `cat $(PIDFILE) 2>/dev/null || true`.
3. If `live` is empty: remove `$(PIDFILE)`, then print `sysmon: not running (nothing to stop)`
   when `tracked` was empty, or `sysmon: not running (removed stale pidfile -> PID $$tracked)`
   when it was not. Exit 0. This is the only branch where the pidfile may be removed without a
   kill, because nothing was running.
4. Otherwise decide which path is being taken, for the report only: if `tracked` is non-empty and
   is a member of the live list — tested with `echo "$$live" | grep -qxF "$$tracked"`, which is a
   whole-line literal match — print `sysmon: stopping tracked PID $$tracked`. Otherwise print
   `sysmon: pidfile missing or stale -- stopping PID(s) found by live scan: $$livelist`. Build
   `livelist` by assigning it from an **unquoted** `$$(echo $$live)`; leaving the expansion
   unquoted is what collapses the newline-separated PID list onto one line for display.
5. Signal every PID in `live` (not just the tracked one, so a tracked instance plus stray orphans
   are all cleared) with a plain `kill $$live 2>/dev/null || true`. Word splitting on the default
   IFS turns the newline-separated list into separate arguments. Send the default SIGTERM — the
   Go binary installs a signal handler and exits promptly.
6. Confirm termination rather than assuming it: loop up to ten times, each iteration reassigning
   `remaining` from `$(PGREP)` (same stderr redirect and `|| true`), breaking out as soon as
   `remaining` is empty, otherwise `sleep 0.2`. A `for` loop does not create a subshell, so
   `remaining` is still readable after the loop.
7. If `remaining` is non-empty after the loop, print `sysmon: FAILED to stop PID(s) $$remaining`
   to stderr, leave `$(PIDFILE)` untouched, and `exit 1`. Only on the success path remove
   `$(PIDFILE)` and print `sysmon: stopped (PID(s) $$livelist)`.

Update the `## stop:` description comment — the parenthetical claiming the stop is driven by the
PID file is now wrong; describe it as stopping the background process, falling back to a live
scan when the pidfile is missing or stale.

Change the `clean` target to declare `stop` as a prerequisite (`clean: stop`), leaving its recipe
body otherwise unchanged. `stop` is already listed in `.PHONY`, so no `.PHONY` edit is needed.
Because a failed `stop` exits 1, make will abort `clean` before it deletes anything — which is the
intended behaviour: `clean` must never outrun an unkilled process.
  </action>
  <verify>
    <automated>bash -c 'set -e; make -s build >/dev/null; make -s start >/dev/null; rm -f /tmp/sysmon.pid; make -s stop; if pgrep -x -U "$(id -u)" sysmon >/dev/null 2>&1; then echo "FAIL: orphan survived stop"; exit 1; fi; if [ -f /tmp/sysmon.pid ]; then echo "FAIL: pidfile not removed after successful stop"; exit 1; fi; make -s start >/dev/null; make -s clean >/dev/null; if pgrep -x -U "$(id -u)" sysmon >/dev/null 2>&1; then echo "FAIL: clean stranded a running process"; exit 1; fi; echo PASS'</automated>
  </verify>
  <done>
The orphan scenario from the bug report is fixed: starting sysmon, deleting the pidfile, then
running `make stop` kills the process and reports that it used the live-scan path. `make clean`
kills before it deletes. `make stop` with nothing running exits 0 and clears any stale pidfile.
A failed kill leaves the pidfile in place and exits non-zero. The verify command prints PASS.
  </done>
</task>

<task type="auto">
  <name>Task 2: Guard start against double-launch and make status report real liveness</name>
  <files>Makefile</files>
  <action>
Add a guard to `start` as its own recipe line, placed after the existing `build` prerequisite and
**before** the `nohup` line — keeping it on a separate line means the guard's shell never carries
the launch arguments in its own argument list. The guard performs both checks the bug calls for:

- First, the pidfile check: if `$(PIDFILE)` exists and `kill -0 "$$(cat $(PIDFILE))"` succeeds,
  and that PID is a member of the `$(PGREP)` output (whole-line literal match, same
  `echo | grep -qxF` test as `stop`), print
  `sysmon: already running, tracked as PID $$tracked -- run 'make stop' first` to stderr and
  `exit 1`. Requiring membership in the live list is what prevents a recycled PID in a stale
  pidfile from producing a false "already running".
- Then the live scan: assign `live` from `$(PGREP)` with the usual stderr redirect and `|| true`;
  if it is non-empty, print `sysmon: already running, untracked PID(s) $$livelist -- run 'make
  stop' first` to stderr and `exit 1`, with `livelist` built from an unquoted `$$(echo $$live)`
  as in `stop`.

Both messages go to stderr and both exit non-zero, so a second `make start` fails loudly instead
of silently spawning the process that becomes the next orphan. Do not put the literal launch
string `./$(BINARY) -quiet` into any echo text in the guard. Leave the existing `nohup` line and
the existing success message unchanged.

Rewrite the `status` recipe as a single logical shell line that computes `live` and `tracked`
exactly as `stop` does, then reports one of four states and always exits 0 (so `make status` is
safe to call from a script):

- `live` empty and `tracked` empty: `sysmon: not running`
- `live` empty and `tracked` non-empty: `sysmon: not running (stale pidfile -> PID $$tracked; run
  'make stop' to clear)`
- `live` non-empty and `tracked` is a member of the live list:
  `sysmon: running, tracked (PID $$tracked)`. Additionally compute the other PIDs with
  `echo "$$live" | grep -vxF "$$tracked"`; if that is non-empty, print a second line
  `sysmon: warning -- extra untracked PID(s) $$others` so a tracked instance coexisting with an
  orphan is still surfaced. Guard that conditional print so a false test does not become the
  line's exit status.
- `live` non-empty and `tracked` absent or not a member:
  `sysmon: running, UNTRACKED (PID(s) $$livelist) -- run 'make stop'`

Keep the three substrings `not running`, `running, tracked` and `running, UNTRACKED` exactly as
written — they are the states the verification greps for, and they are mutually exclusive under a
literal match. Update the `## status:` description comment to say it reports live processes, not
just pidfile state.
  </action>
  <verify>
    <automated>bash -c 'set -e; make -s build >/dev/null; make -s stop >/dev/null 2>&1 || true; make -s status | grep -qF "not running" || { echo "FAIL: idle status"; exit 1; }; make -s start >/dev/null; make -s status | grep -qF "running, tracked" || { echo "FAIL: tracked status"; exit 1; }; if make -s start >/dev/null 2>&1; then echo "FAIL: second start was allowed"; exit 1; fi; rm -f /tmp/sysmon.pid; make -s status | grep -qF "running, UNTRACKED" || { echo "FAIL: orphan status"; exit 1; }; make -s stop >/dev/null; make -s status | grep -qF "not running" || { echo "FAIL: status after stop"; exit 1; }; echo PASS'</automated>
  </verify>
  <done>
A second `make start` refuses and exits non-zero while the first instance keeps running.
`make status` reports all three required states — tracked, untracked orphan, not running — plus
the stale-pidfile-with-nothing-running case. The verify command prints PASS and leaves no sysmon
process behind.
  </done>
</task>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| make recipe -> OS process table | The recipes choose signal targets from a pattern match; a wrong match sends SIGTERM to a process the user did not intend to kill. |
| /tmp/sysmon.pid -> kill target | `/tmp` is world-writable and the pidfile is unprivileged; its contents are attacker-influencable input to `kill`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-PN8-01 | Denial of Service | `stop` / `clean` process match | high | mitigate | Match with `pgrep -x` on the exact process name instead of `-f` on the argument list. Verified during planning: `pgrep -f sysmon` returns the live macOS daemon `/usr/libexec/sysmond` (PID 92862), `pgrep -x sysmon` does not. Also forbids `pkill -f`. |
| T-PN8-02 | Denial of Service | `stop` cross-user match | medium | mitigate | Restrict every scan with `-U $$(id -u)` so a same-named process owned by another user or by root is never a signal target. |
| T-PN8-03 | Tampering | stale `$(PIDFILE)` with a recycled PID | medium | mitigate | The pidfile PID is honoured only when it is a member of the live-scan list; the kill always targets the scan output, never the raw file contents. |
| T-PN8-04 | Tampering | attacker-written `/tmp/sysmon.pid` | low | mitigate | Covered by T-PN8-03: an injected PID is ignored unless it is also a live process whose exact name is `sysmon` and whose owner is the invoking user. |
| T-PN8-05 | Denial of Service | recipe shell self-match | low | mitigate | Name-based matching cannot match the recipe's own `/bin/sh` (name `sh`); the `start` guard is additionally kept on a recipe line separate from the launch line. |

No package-manager installs are in scope (Makefile edit only, stdlib-only project), so no
supply-chain legitimacy checkpoint is required.
</threat_model>
